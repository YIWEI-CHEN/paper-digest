01釐清產品目標Clarify product goals

先定義決策與目標。 問版位是搜尋廣告還是動態消息、CPC 還是 CPA、最佳化有效點擊還是轉換價值。先聚焦 CPC，CTR 是模型輸出，不是唯一產品 KPI。主指標可用每千次有效曝光收入，護欄看轉換品質、隱藏／檢舉、延遲與長期留存。

假設再估容量。 練習假設尖峰 10k requests/s，每次 200 個候選，排序服務 p95 100 ms；這代表約 2M candidate scores/s。先確認能否批次評分、特徵快取，以及候選預篩選。

Define the decision and objective. Ask whether this is search or feed advertising, CPC or CPA billing, and whether value means qualified clicks or conversions. For this exercise, use CPC. CTR is a model output, not the sole product KPI. Consider revenue per thousand valid impressions, with conversion quality, hides/reports, latency, and retention as guardrails.

State scale assumptions. Assume a peak of 10k requests/s, 200 candidates per request, and a 100 ms p95 ranking-service budget. That is about 2M candidate scores/s, motivating batched scoring, cached features, and candidate pruning. These are interview assumptions.

02資料與標籤Data & labels

樣本是曝光，不是所有廣告配對。 impression_id 連結 user/ad/context、曝光位置、候選集合、policy/model version、時間與點擊事件；重複點擊與機器流量需處理。用事先定義的點擊歸因窗口，窗口成熟後才把無點擊標成 0。

只用當時可取得的資訊。 特徵包含歷史偏好、廣告文字／圖片表示、時間、裝置與曝光前統計；做 point-in-time join。以時間做 train/validation/test，轉換另處理延遲。負例下採樣要記錄抽樣率；未曝光廣告沒有可直接觀察的點擊標籤。

Use impressions as examples. Join impression_id to user/ad/context features, position, candidate set, policy/model versions, timestamps, and click events. Deduplicate clicks and handle invalid traffic. Define a click-attribution window and only label a non-click after that window matures.

Use information available at decision time. Features include prior behavior, creative text/image representations, device, time, and pre-impression aggregates. Use point-in-time joins and chronological train/validation/test splits. Handle conversion delays separately. Record negative-sampling rates; unshown ads do not have observed click labels.

03Baseline／模型Baseline & models

先建立能解釋的 baseline。 以版位／廣告類別的平滑 CTR，加 logistic regression 或 GBDT，檢查資料與增益。大規模稀疏類別特徵再用 embedding＋特徵交互模型，例如 DLRM 類設計；文字／圖片 encoder 可離線產生表示。

把目標函數說清楚。 用 binary cross-entropy 學 p(click | user, ad, context, shown)。以自然流量分布的獨立驗證集做校準。若多任務學 click/conversion/hide，要解釋 loss 權重、標籤稀疏與不同歸因窗口；不要直接把 click-conditional CVR 當成曝光轉換率。

Start with an interpretable baseline. Use smoothed CTR by placement/category, then logistic regression or GBDT to verify data quality and incremental value. For large sparse feature spaces, consider embeddings and explicit feature interactions, such as a DLRM-style model. Encode text and images offline where feasible.

Specify the learning objective. Binary cross-entropy estimates p(click | user, ad, context, shown). Calibrate on a separate validation set with natural traffic prevalence. A multitask click/conversion/hide model requires explicit loss weights and attribution windows. Click-conditional CVR is not the same as impression-level conversion probability.

04訓練與部署Training & deployment

建立兩條資料路徑。 曝光／點擊事件進串流與離線儲存，經 watermark、去重、標籤成熟與特徵驗證後訓練；近期計數更新線上 feature store。每日重訓可作起點，依 drift 與收益調整頻率。

上線要可回復。 將模型、特徵 schema、校準器一起版本化；離線回放 → shadow → 小流量 canary → A/B。特徵超時時回退到缺失值已訓練的輕量模型；預算、資格與頻控仍由約束服務執行。監控 feature age、缺失率、p95/p99、預測 CTR 與實際 CTR。

Build offline and online data paths. Impression/click streams feed durable storage, deduplication, watermarking, label maturation, and training validation. Recent counters update an online feature store. Daily retraining is a starting assumption; adjust it based on drift and measured value.

Make releases reversible. Version the model, feature schema, and calibrator together. Progress through replay, shadow traffic, a canary, and A/B testing. On feature timeouts, use a lightweight model trained to handle missingness. Eligibility, budgets, and frequency caps remain enforced. Monitor feature age, missingness, p95/p99 latency, and predicted versus observed CTR.

05離線評估／線上實驗Offline evaluation & online experiments

離線分開看排序與機率。 ROC-AUC 看整體區分能力；PR-AUC 要搭配正例率解讀；log loss、Brier score、reliability diagram 檢查機率。依版位、新廣告、裝置、地區與活躍度切片，並在原始分布評估。

線上驗證產品效果。 穩定 user-level 分流，先查 SRM、曝光與點擊日誌完整性；預先定主指標、MDE、樣本量與觀察窗。廣告預算可能造成組間干擾，必要時採 campaign/geo 層級設計。收入提升須同時通過使用者與廣告主護欄；保留快速 rollback。

Separate ranking from probability quality. ROC-AUC measures discrimination; interpret PR-AUC alongside prevalence. Use log loss, Brier score, and reliability diagrams for probability quality. Evaluate on natural traffic and slice by placement, new ads, device, geography, and activity level.

Test product impact online. Use stable user assignment, check SRM and logging completeness, and predefine the primary metric, MDE, sample size, and duration. Shared campaign budgets may create interference, requiring campaign- or geo-level designs. Revenue gains must pass user and advertiser guardrails, with fast rollback available.

06失敗案例與取捨Failures & tradeoffs

AUC 上升但收入下降： 先查校準、分群偏差、候選集合、延遲與預算消耗，不要直接重訓更大模型。新廣告沒曝光： 用內容特徵與受限探索，而非只靠 ID embedding。

主要取捨。 點擊誘餌可能推高 CTR 卻降低轉換和信任；即時特徵增加新鮮度也增加依賴與延遲。以最低必要特徵、分層 fallback、自然分布校準及探索資料減少 feedback loop。隨流量成長，先量測 feature fetch 與 embedding table 瓶頸再擴模型。

AUC rises but revenue falls: inspect calibration, slice shifts, candidate composition, latency, and budget consumption before increasing model size. New ads receive no exposure: add content features and constrained exploration rather than relying only on ID embeddings.

Main tradeoffs. Clickbait can increase CTR while hurting conversions and trust. Fresh features improve responsiveness but add dependencies and latency. Use minimal necessary features, layered fallbacks, natural-distribution calibration, and exploration data to limit feedback loops. Profile feature fetching and embedding tables as traffic grows.

深入拆解Deep dives

下採樣與機率校準Downsampling and calibration

若所有正例保留、負例以 r 的機率保留，抽樣資料預測 q 對應真實 p = r·q / (1−q+r·q)。例如 r=0.1、q=0.2，p≈0.0244。此式假設類別內隨機抽樣；不適用於任意 hard-negative sampling。可用正確 sample weights 直接學原分布，但不要再重複做同一抽樣修正；校準仍須獨立驗證。

If all positives are retained and each negative is retained with probability r, a sampled-data estimate q corresponds to p = r·q / (1−q+r·q). With r=0.1 and q=0.2, p≈0.0244. This assumes random sampling within each class, not arbitrary hard-negative mining. Correct sample weights can target the original distribution directly; do not apply the same correction twice. Validate calibration separately.

預測、價值與拍賣分層Separate prediction, value, and auction policy

簡化 CPC 期望 eCPM = 1000 × bid_per_click × pCTR，單位是每千次曝光的期望出價價值。這不是完整拍賣或實收收入公式。若轉換只能在點擊後發生，pCVR_per_impression = pCTR × p(conversion | click)；若有 view-through conversion，需另定義。品質、相關性、預算 pacing 與頻控不能靠同一乘積全部解決。

A simplified CPC expected-value score is eCPM = 1000 × bid_per_click × pCTR. Its units are expected bid value per thousand impressions; it is not a full auction or realized-revenue formula. If conversion requires a click, pCVR_per_impression = pCTR × p(conversion | click). View-through conversions need a separate definition. Quality, relevance, pacing, and frequency constraints require explicit policy handling.

100 ms 如何分配？How would you budget 100 ms?

練習預算：特徵 20 ms、批次推論 40 ms、約束與回應 20 ms、預留 20 ms。這只是 critical-path 設計額度；各階段 p95 不能直接相加當成端到端 p95。以真實負載測試長尾、候選數與 cache miss，超時優先減少候選或回退輕量模型。

An illustrative budget is 20 ms for features, 40 ms for batched inference, 20 ms for constraints/response, and 20 ms of slack. These are critical-path allocations: adding stage p95 values does not produce an end-to-end p95. Load-test tail latency, candidate counts, and cache misses. Reduce candidates or fall back to a lightweight model on deadline pressure.

面試官追問 → 建議回答Follow-up questions → suggested answers

為什麼 AUC 好還需要 calibration？Why calibrate if AUC is strong?

AUC 只看相對排序；相同 AUC 的模型可以輸出差很多的機率。出價價值與預算決策依賴機率絕對值，所以必須另外驗證。

AUC depends on ordering, while bid-value and budget decisions depend on absolute probabilities. Models with identical AUC can have very different calibration.

曝光位置可以當特徵嗎？Can position be a feature?

可以建模展示條件，但必須有一致的 serving 定義；不要把舊排序位置當成內在相關性。用受控探索估計曝光傾向，必要時做偏差修正；低 propensity 會造成高方差。

It can model presentation context if serving semantics are consistent. Do not mistake the old rank position for intrinsic relevance. Controlled exploration can estimate exposure propensities; corrections require care because small propensities create high variance.

02資料與標籤Data & labels

分清行為的含義。 記錄 request_id、候選／展示商品、位置、click/cart/order/return、時間與模型版本；只有顯示後無互動才可當弱負例，未展示商品屬未知。購買比點擊稀疏，退貨標籤更晚成熟，需多個標籤窗口。

Distinguish behavioral signals. Log request_id, candidate and displayed items, positions, clicks, carts, orders, returns, timestamps, and model versions. Displayed-but-ignored items are weak negatives; unshown items are unknown. Purchases are sparser than clicks, and returns mature later, requiring separate label windows.

Make examples reproducible. Use pre-request history, session intent, category, price, text/image features, and inventory snapshots. Do not use future prices or post-purchase attributes. Split chronologically and retain cold-user/item slices. Normalize product variants and duplicate listings.

兩階段模型有不同任務。 先用熱門、同類別與 item-to-item 共購產生候選；再加雙塔 user/session encoder 與 item encoder，以對比或 sampled-softmax 目標學可快速檢索的向量。in-batch negatives 可能是假負例，需考慮熱門度抽樣偏差與同商品變體。

Give retrieval and ranking distinct jobs. Start with popular items, category candidates, and item-to-item co-purchase signals. Add a two-tower user/session and item model using a contrastive or sampled-softmax objective. In-batch negatives may be false negatives; account for popularity-driven sampling and product variants.

Use richer interactions in ranking. A GBDT or deep ranker predicts clicks, carts, purchases, and returns. Combine these through an explicit utility function and hard constraints. User/item towers and the index must be compatible; switch atomically and retain the previous version. Features, models, and indexes all need rollback paths.

Separate freshness requirements. Descriptions change slowly, session intent updates via streams, and price/inventory comes from an authoritative service with explicit TTLs. Filter during retrieval and recheck before output. Do not encode live stock as a permanent embedding property. Fall back to eligible popular or recently viewed items on ANN failure.

05離線評估／線上實驗Offline evaluation & online experiments

分層診斷。 用已知相關商品量測候選 Recall@K，再量測精排 NDCG@K、purchase log loss 與 calibration；檢查 catalog coverage、類別多樣性與冷啟動切片。ANN recall 是相對 exact-nearest-neighbor 的近似精度，與行為相關性的 retrieval recall 不同。

A/B 以 user 為單位。 預設樣本量與實驗時長，先查 SRM；看 orders/user 與增量收益，同時等待取消／退貨成熟。若只是把首頁購買搬到另一個入口而非新增，要用整體使用者指標辨識 cannibalization。

Diagnose by stage. Measure candidate Recall@K against known relevant items, then ranker NDCG@K, purchase log loss, and calibration. Check catalog coverage, diversity, and cold-start slices. ANN recall measures agreement with exact nearest-neighbor search; it is different from relevance recall.

Randomize by user. Predefine power and duration, check SRM, and measure orders per user and incremental value while allowing cancellation/return labels to mature. Whole-user metrics help distinguish additional purchases from moving purchases between surfaces.

06失敗案例與取捨Failures & tradeoffs

新使用者： 用上下文、session、熱門與可選偏好；新商品： 用 metadata／圖文表示與受限探索。過度個人化： 重排加入類別／品牌多樣性、避免重複商品與已不需要的耐久財。

主要取捨。 ANN 召回速度對長尾 recall；更大 ranker 對延遲；即時行為對噪音與隱私。先分析是「好商品沒召回」還是「召回後排錯」，再投資對應階段。以探索與跨時段評估減少熱門度 feedback loop。

New users: use context, session behavior, popularity, and optional preferences. New products: use metadata, image/text representations, and constrained exploration. Overspecialization: add category/brand diversity and suppress duplicates or no-longer-needed durable goods.

Main tradeoffs. ANN speed competes with long-tail recall; larger rankers compete with latency; real-time behavior adds both freshness and noise. Determine whether useful items were missed by retrieval or misordered after retrieval before investing. Exploration and temporal evaluation help limit popularity feedback loops.

At 5k requests/s and 200 final-ranker candidates, demand is 1M scores/s. Derive capacity from measured batch latency, hardware throughput, and failover headroom, not raw-vector size alone.

為什麼不是一個模型排全部商品？Why not score every product with one model?

10M 商品逐一做昂貴 cross-feature 計算太慢。雙塔能預先算商品向量，快速找候選；精排則對少量候選使用 user–item 深度交互。代價是兩階段最佳化不完全一致，且召回漏失無法由 ranker 補救，因此要追蹤各召回來源的 coverage 與增量價值。

Expensive cross-feature scoring over 10M products is impractical per request. Two towers permit precomputed item vectors and fast retrieval; the ranker spends richer user–item interactions on a small candidate set. The objectives may differ, and a ranker cannot recover omitted items, so measure coverage and incremental value by candidate source.

如何處理負樣本？How would you sample negatives?

檢索可混合 random、in-batch 與 hard negatives，排除已知正例與重複商品；評估抽樣分布是否偏熱門。精排優先使用同次曝光集合的成熟結果，並區分無互動與明確不喜歡。曝光偏差需額外探索資料或有假設條件的 propensity correction；不是換一種 loss 就消失。

Retrieval can mix random, in-batch, and hard negatives while excluding known positives and duplicates. Inspect popularity bias in sampling. Ranking should use matured outcomes from impression sets and distinguish non-interaction from explicit dislike. Exposure bias requires exploration data or assumption-dependent propensity correction; a new loss alone does not remove it.

Hybrid retrieval 的可計算說法A concrete hybrid-retrieval explanation

RRF(d) = Σ 1 / (c + rank_i(d))，未出現在某一路結果則那一路不貢獻分數；c 是調整常數。練習可從 BM25 100＋dense 100 合併去重，rerank 50，再選 8 個片段，但 K、c、chunk size 都要以品質／延遲 ablation 決定。保留同一文件的必要上下文，避免八個片段只是同一句的重複。

RRF(d) = Σ 1 / (c + rank_i(d)); a source contributes nothing when d is absent from its list. The constant c controls rank sensitivity. An illustrative setup retrieves 100 BM25 and 100 dense results, reranks 50 deduplicated candidates, and selects 8 chunks. Tune K, c, and chunk size through quality/latency ablations, and avoid filling context with duplicates.

Check SRM/logging before effect sizes and confidence intervals. Do not stop merely because one day's p-value drops below 0.05. Sequential testing needs a valid prespecified procedure. Shared ad budgets, social ties, and marketplaces may require different assignment designs.

01 · 目標有決策單位A concrete decision unit

Give a baseline, explain the loss/output, and specify when complexity becomes worthwhile.

畫出資料流、版本和新鮮度；有容量估算、timeout fallback 與 rollback。

Draw data flow, versions, and freshness. Include capacity, timeout fallback, and rollback.

分開元件與端到端指標，說明切分、切片、分流、護欄與實驗可信度。

Separate component and whole-system metrics; explain splits, slices, assignment, and experiment validity.

06 · 取捨可被檢驗Tradeoffs are testable

至少說一個 failure → detection → mitigation，並用品質／延遲／成本決定下一步。

State a failure → detection → mitigation chain, and choose the next step using quality, latency, and cost.

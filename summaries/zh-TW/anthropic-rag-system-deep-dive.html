01 / SCOPE

先定義什麼是成功回答Define a successful answer first

設計一個回答私有文件問題的 RAG 系統：支援持續更新、使用者權限、可驗證引用，以及證據不足時的適當行為。題目名稱是練習標籤，本篇不是 Anthropic 內部架構。

Design a RAG system over private documents with continuous updates, user permissions, verifiable citations, and appropriate behavior when evidence is insufficient. The challenge name is a practice label; this is not Anthropic's internal architecture.

貫穿全篇：Atlas v2 API 文件Running example: Atlas v2 API documentation

使用者問：「Atlas v2 的批次上傳遇到 429 應如何重試？哪些錯誤不能重試？請引用文件。」知識庫同時有 v1、v2、重試指南和受限事故報告。Atlas、流量、容量及延遲預算都是教學假設。

The user asks: “How should Atlas v2 batch uploads retry a 429? Which errors must not be retried? Cite the documentation.” The corpus contains v1/v2 specifications, retry guides, and restricted incident reports. Atlas, traffic, capacity, and latency budgets are illustrative assumptions.

Success requires a correct and sufficiently complete answer, important claims supported by authorized version-appropriate evidence, and an honest account of gaps. “Retry any error” can fail despite real citations if it omits non-retryable errors or idempotency conditions. Citation clicks are secondary signals: users may click out of trust or skepticism.

為什麼不直接把所有文件放進長 context？Why not put every document into a long context?

小而穩定、完全授權的集合值得作 long-context baseline。較大的語料還要考慮成本、無關內容、更新及權限。用相同問題比較品質與成本，而不是把 RAG 當成先驗必要。歷史論文的模型排序不保證適用目前模型。

For a small, stable, fully authorized corpus, long context deserves a baseline. Larger corpora add cost, distractors, updates, and access constraints. Compare quality and cost on the same tasks instead of assuming RAG is necessary. Historical model rankings need not hold for current models.

02 / ARCHITECTURE

把候選、原始證據與回答責任分開Separate candidates, source evidence, and answers

線上路徑由明確契約連接：查詢條件 → 授權檢索 → 精排 → 原文與版本檢查 → evidence packing → 回答。離線建立索引，線上仍需檢查目前權限與刪除狀態。

Connect the online path through explicit contracts: query scope → authorized retrieval → reranking → source/version checks → evidence packing → answering. Offline indexing never replaces current authorization and deletion checks.

檢索表示不等於原文Representation is not source evidence

retrieval_text 可包含標題或生成 context；raw_text 與 source spans 必須保留，讓引用不依賴模型重寫。

retrieval_text may include titles or generated context. Preserve raw_text and source spans so citations never depend on a model's rewrite.

有界 workflow 起步Start with a bounded workflow

第一版固定主要步驟；只有版本不明或證據缺口才允許澄清／補查。保存 call budget、deadline 和目前已覆蓋的子問題。

Fix the main path initially. Allow clarification or extra search for ambiguous scope or missing evidence, with call budgets, deadlines, and tracked subquestion coverage.

版本和權限是硬限制Version and access are constraints

舊版文件的高相似度不能覆蓋明確的 v2 條件；未授權證據不能先交給外部 reranker／LLM 再刪掉答案。

A highly similar old document cannot override an explicit v2 constraint. Unauthorized evidence must not reach external rerankers or LLMs before being filtered from the answer.

多輪對話只保存有來源的狀態與使用者已確認的條件：產品、版本、時間、尚未解答的部分。上一輪模型產生的摘要不是新證據。若使用者從 v1 改問 v2，清除不適用的 evidence 與 answer cache，而不是繼續沿用舊上下文。

Across turns, preserve sourced state and confirmed constraints: product, version, time, and unresolved questions. A previous model summary is not new evidence. When the user switches from v1 to v2, invalidate incompatible evidence and answer caches rather than carrying old context forward.

把 chunking 當成實驗變因Treat chunking as an experimental variable

Start with section, paragraph, table, or function boundaries, then compare token caps such as 256/512/1024 and overlap. These are candidate settings, not optimal values. Measure required-evidence recall, noise, duplication, and cost. Label gold evidence on source spans, then map it to each chunker.

怎麼防止 train／test 洩漏？How do you prevent train/test leakage?

按文件家族、產品或時間分組，讓近似版本、相鄰 chunks、中英翻譯留在同一 split。保留獨立人工測試題；不要用 test 問題生成 contextual text 或調閾值。另建未見領域／版本切片。索引可包含測試時合法可讀的文件，但不能把測試答案標籤餵入訓練。

Group by document family, product, or time, keeping near versions, neighboring chunks, and translations together. Hold out human-authored questions; never use test queries for contextualization or threshold tuning. Add unseen-domain/version slices. The index may contain documents legitimately available at test time, but training must not consume held-out answer labels.

05 / RETRIEVAL

Baseline、特徵與多階段檢索Baselines, features, and multi-stage retrieval

用失敗類型決定模型升級，先把資料和簡單基準做對。BM25 處理精確詞彙，dense 補語意，cross-encoder 在有限候選上建模交互。

Let failure analysis drive model upgrades after validating data and simple baselines. BM25 handles exact terms, dense retrieval adds semantic matching, and a cross-encoder models interactions over a bounded candidate set.

候選越多一定越好嗎？Are more candidates always better?

更多召回可能提高 evidence recall，但增加精排成本與噪音；更多送入 prompt 的 chunks 又是另一個預算。分開掃描 retrieval K、rerank N 與最終 token budget，畫品質／延遲／成本曲線。合併重複來源，防止同一段的 overlap 占滿前幾名。

More retrieved candidates may improve evidence recall while increasing reranking cost and noise. Final prompt chunks are a separate budget. Sweep retrieval K, rerank N, and context tokens independently, then compare quality/latency/cost curves. Collapse overlapping duplicates that would otherwise consume top ranks.

06 / CONTEXTUAL

Contextual Retrieval：脈絡、成本與血緣Contextual Retrieval: context, cost, and provenance

這是一種檢索表示的改善：讓一段孤立文字帶有足以辨識文件、版本和主題的脈絡，再做索引。它不會自動讓生成的 context 成為可信事實。

This improves retrieval representations by giving isolated passages enough context to identify their document, version, and subject before indexing. It does not automatically make generated context a trusted fact.

教學例子：同一段文字的兩種用途Illustrative example: two uses of the same passage
raw_text = 'These requests should not be retried.'
context_text = (
    'This passage describes non-retryable validation failures '
    'in the Atlas v2 batch-upload specification.'
)
retrieval_text = context_text + '\n\n' + raw_text

# Store separately:
# raw_text + document_version + source_span → evidence and citation
# retrieval_text + contextualizer_version  → lexical/dense indexing

Anthropic 的 2024 年實驗把 chunk-specific context 用在 embeddings 與 BM25。原文 top-20 retrieval failure 從 5.7% 降到 2.9%，加 reranking 後到 1.9%，相對下降約 49% 與 67%。這是作者特定設定的檢索結果，不是回答正確率增加 67 個百分點。

Anthropic's 2024 experiments used chunk-specific context for embeddings and BM25. Reported top-20 retrieval failure fell from 5.7% to 2.9%, and to 1.9% with reranking: relative reductions of about 49% and 67%. These are retrieval results under the authors' settings, not a 67-percentage-point answer-accuracy gain.

比較真正的增益來源Identify the source of improvement

比較 raw chunk、title path、文件摘要與 chunk-specific context。其餘模型、問題、候選及 token 預算固定，避免把多個變更一起歸因給 contextualization。

Compare raw chunks, title paths, document summaries, and chunk-specific context while holding other models, questions, candidates, and token budgets fixed.

更新有寫入放大Updates can amplify work

Context 依賴父文件；父文件變動時，原文未改的 chunk 也可能要重產 context 和 embedding。記錄 dependency hash，而不只檢查 raw chunk hash。

Context depends on its parent document. A parent update may require regenerating context and embeddings for unchanged raw chunks. Track dependency hashes, not only raw-chunk hashes.

衍生內容繼承權限Derived content inherits access limits

不能用受限段落補出公開 chunk 的摘要。若多來源共同生成 context，可讀者必須符合所有來源限制，或在一致權限範圍內分別產生。

Do not enrich a public chunk with restricted passages. Multi-source derived context must respect every source's access restrictions, or be generated separately within consistent access scopes.

離線處理可批次化並重用穩定文件 prefix 的 prompt cache，但 cache hit 不是免費、零延遲或保證。量測每文件 contextualization tokens、失敗重試、更新放大和每個品質增益的成本。沒有脈絡缺失的資料，不一定值得增加這一層。

Offline processing can batch work and reuse stable document prefixes through prompt caching, but hits are not free, instantaneous, or guaranteed. Measure contextualization tokens per document, retries, update amplification, and cost per quality gain. Corpora without context-loss failures may not justify this layer.

生成 context 出現原文沒有的版本資訊怎麼辦？What if context invents a version?

Contextualizer 的輸入只能來自適當來源；產物要驗證 metadata 一致性並抽樣人工稽核。確定版本以來源 metadata 為準，不能被生成文字覆寫。可退回 title path＋raw text，並把此類錯誤加入回歸集。

Restrict contextualizer inputs to appropriate sources, validate metadata consistency, and sample outputs for human review. Authoritative version metadata overrides generated text. Fall back to title paths plus raw text and add the failure to regression evaluation.

    identity = authenticate_server_side(request)
    scope = resolve_query_scope(request.query, identity)
    acl = current_authorization(identity)
    manifest = compatible_index_manifest()

    # Both retrievers enforce trusted scope and authorization.

        deadline=deadline

    raw = fetch_versioned_source_spans(ranked)

    packet = pack_support_and_exceptions(evidence, token_budget)
    decision = calibrated_answer_policy(packet, scope)
    # A bounded workflow may retrieve missing evidence, then repeat gates.
    if decision.requires_clarification_or_abstention:
        return explicit_partial_or_no_answer(decision)

    draft = generate_with_citations(request.query, packet)
    checked = validate_source_mapping_and_claims(draft, packet)
    # Release only if dependencies still satisfy the access contract.
    return release_or_stop(checked, identity, current_authorization(identity))

45 分鐘面試流程與中英口說稿A 45-minute interview flow and bilingual talk track

00–05 分鐘 · 釐清產品目標00–05 min · Clarify product goals

我會先確認文件範圍、是否有不同使用者權限、問題是問目前還是歷史版本，以及延遲與成本預算。成功不是產生流暢文字，而是正確且足夠完整的回答，有適用且授權的來源支持；證據不足時能澄清或限定回答。我會以私有 API 文件問答為例，先做固定檢索流程，保留有界補查作延伸。

I would first clarify the corpus, user-specific permissions, current versus historical questions, and latency and cost budgets. Success is a correct, sufficiently complete answer supported by applicable, authorized sources, with clarification or a limited answer when evidence is missing. I would use private API documentation as the working example, starting with a fixed retrieval workflow and reserving bounded additional search for gaps.

05–12 分鐘 · 資料與標籤05–12 min · Data and labels

每份文件保留穩定 ID、版本、有效時間、ACL 和原始位置；解析表格與程式碼時保留結構。我會把 raw evidence 與 contextual retrieval text 分開。標籤分成 query scope、相關 passage、必要 supporting facts、答案與拒答行為。用真實問題建立 gold set，合成問題補不足的切片；切分時按文件家族、時間和問題改寫分組，避免洩漏。

Each document keeps a stable ID, version, effective time, ACL, and source positions, with structure preserved for tables and code. I would separate raw evidence from contextual retrieval text. Labels cover query scope, relevant passages, required supporting facts, answers, and abstention behavior. Real questions anchor the gold set; synthetic questions supplement missing slices. Splits group document families, time periods, and question paraphrases to prevent leakage.

12–25 分鐘 · Baseline、模型與架構12–25 min · Baselines, models, and architecture

先比較 BM25 和 dense retrieval，再做 hybrid fusion、cross-encoder reranking 和有限 token 的 evidence packing。BM25 處理精確識別碼，dense 處理語意改寫，reranker 在較小候選集合做細緻交互。若看到 chunk 缺脈絡的錯誤，再測 title path 與 Contextual Retrieval。需要訓練時，用 query–passage 正負例訓練 retriever，對固定候選做 reranker supervision；錯版本可當 hard negative，但先檢查它是否是比較題的正例。

I would compare BM25 and dense baselines, then add hybrid fusion, cross-encoder reranking, and token-budgeted evidence packing. BM25 handles exact identifiers, dense retrieval handles paraphrases, and rerankers model richer interactions over fewer candidates. If chunks lack context, I would test title paths and Contextual Retrieval. For training, use query–passage positives and negatives for the retriever and fixed-candidate supervision for the reranker. A wrong version is a hard negative only if it is not relevant to a comparison question.

25–33 分鐘 · 訓練與部署25–33 min · Training and deployment

我會把 encoder 和索引當相容版本發布，保留模型、prompt、資料和授權 trace。文件更新用冪等 upsert，刪除與撤權走獨立失效路徑。快取包含 scope 和證據版本，而且取用時重驗授權。Serving 設整體 deadline、候選上限和有限補查；reranker 超時可以退回 fusion，但權限失效不能降級放行。先 shadow，再 canary，並確保 rollback 不會恢復已撤銷的資料。

I would release compatible encoder/index versions and trace model, prompt, data, and authorization state. Ingestion uses idempotent upserts, with a separate invalidation path for deletion and revocation. Caches include scope and evidence versions and revalidate access on use. Serving has an overall deadline, candidate caps, and bounded retries. Reranker timeouts may fall back to fusion; failed authorization cannot fail open. I would shadow, then canary, with rollback that never restores revoked content.

33–41 分鐘 · 離線評估與線上實驗33–41 min · Offline evaluation and online experiments

我會分開量測 evidence Recall@k、token budget 內必要證據、答案正確性與完整性、citation support，以及拒答的 coverage–risk。用 gold evidence 測 generator，用固定候選測 reranker，才知道瓶頸。Contextualization 和 reranking 做受控 ablation；LLM judge 用人工集校準。通過版本、ACL 與 injection 回歸後才做線上分流，主要看任務完成與修正率，同時守住延遲、成本和 unsupported claims。

I would separately measure evidence Recall@k, required evidence within the token budget, answer correctness and completeness, citation support, and coverage–risk for abstention. Oracle evidence isolates generator errors; fixed candidates isolate reranker errors. Contextualization and reranking need controlled ablations, with judges calibrated against human labels. After version, ACL, and injection regressions pass, online experiments measure task completion and corrections, with latency, cost, and unsupported claims as guardrails.

41–45 分鐘 · 失敗案例與取捨41–45 min · Failures and tradeoffs

我會用一個失敗把設計串起來：系統找到 v1 的正確段落，卻回答 v2 問題。先檢查 scope 和 metadata，再看候選、reranking 和 packing，最後才是 generator。加大 top-k 可能改善 recall，但增加成本和干擾；多步 agent 可能補證據，但增加尾端延遲與失敗面。我的選擇是以逐題診斷決定增加哪個元件，並保留清楚的部分回答與降級行為。

I would connect the design through one failure: the system retrieves a correct v1 passage for a v2 question. Check scope and metadata, then candidates, reranking, and packing, before blaming the generator. Larger top-k may improve recall but adds cost and distractors. Multi-step agents can recover evidence but increase tail latency and failure surfaces. I would add components based on per-query diagnosis and preserve explicit partial-answer and fallback behavior.

追問 · 離線提升，線上卻沒有改善？Follow-up · Offline gains do not improve online outcomes?

先確認分流、版本和 logging 正確，再檢查資料分布與 metric 是否對準任務。可能提升了容易題的 recall，卻沒改善多跳完整性；也可能 latency 增加抵銷品質。用真實失敗問題、語言、freshness、tenant 和 query 難度切片定位，重新看整體效益及不確定性，而不是只要求換更大的模型。

First verify randomization, deployed versions, and logging, then examine distribution and metric alignment. Recall may improve on easy questions without improving multi-hop completeness, or added latency may offset quality. Slice real failures by language, freshness, tenant, and difficulty and assess overall benefit and uncertainty before changing model size.

追問 · Timeout、無結果與不可回答是一樣的嗎？Follow-up · Are timeouts, empty retrieval, and unanswerable questions equivalent?

不一樣。Timeout 是系統未完成證據搜尋；empty retrieval 是這個檢索策略未找到授權候選；unanswerable 是在題目和可用證據定義下無法支持答案。分開記錄並採不同重試或回應，否則會把可靠性問題錯算成正確拒答。

No. A timeout means evidence search did not complete; empty retrieval means this strategy found no authorized candidates; unanswerable means the defined task and available evidence do not support an answer. Log them separately and use different retries or responses, or reliability failures may be miscounted as correct abstentions.
